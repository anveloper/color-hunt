# 컬러헌트 (Color Hunt) — 기획서

## 1. 프로젝트 개요

### 1.1 컨셉
"컬러헌트(Color Hunt)"는 최근 유행하는 소셜 활동을 디지털로 옮긴 **순수 프론트엔드 웹 앱**이다.

> **컬러헌트란?**
> 팀 또는 개인이 여행/일상을 다니며 **지정된 한 가지 색상이 80% 이상 차지하는 사진**을 모아, 9컷(또는 다른 그리드) 콜라주로 배치하여 인스타그램과 같은 세로형 소셜 미디어에 공유하는 활동.

본 앱은 사용자가 모바일로 접속해 사진을 그리드에 배치하고, 하나의 이미지로 다운로드해 SNS에 공유할 수 있도록 돕는다.

### 1.2 핵심 가치
- **서버리스**: 사용자의 사진은 어떠한 서버에도 업로드되지 않는다. 모든 처리는 브라우저 내에서 이루어지며 상태는 LocalStorage로 보존된다.
- **모바일 퍼스트**: PC로 접속하더라도 모바일 뷰포트로 강제 렌더링한다.
- **가볍고 직관적인 UX**: 온보딩 → 편집 두 스텝의 단순한 흐름.
- **개성 있는 비주얼**: Excalidraw 스타일(손으로 그린 느낌)의 타이포/버튼.

### 1.3 비범위(Out of Scope)
- 회원가입, 로그인, 백엔드 API
- 사진의 색상 분석/검증(80% 색상 충족 여부 자동 판정)
- 소셜 공유 기능 직접 통합(다운로드 후 사용자가 직접 업로드)
- 데스크톱 전용 레이아웃

## 3. 기능 명세

### 3.1 온보딩 페이지
- **타이틀**: "컬러헌트" (스타일 손글씨 폰트)
- **버튼**: "시작하기" (연필로 그린 듯한 거친 외곽선)
- **클릭 시**: `/hunt`로 이동
- **스타일 레퍼런스**:
  - 폰트: Caveat / Kalam / 손글씨 류
  - 외곽선: SVG roughjs 스타일(거친 라인)
  - 배경: 종이 질감 또는 오프-화이트(#FAF8F3)

### 3.2 그리드 편집 페이지

#### 3.2.1 그리드 레이아웃
디바이스 화면 비율(가로:세로)에 그리드를 가득 채워 배치한다. 사진 한 장을 그리드 셀로 자른 듯한 느낌을 위해 **셀 사이 간격(gutter)은 0**, 그리드 선은 오버레이로 그린다.

| 레이아웃 | 열x행 | 셀 개수 | 비고 |
|---|---|---|---|
| 3x3 | 3 x 3 | 9 | **기본값** |
| 3x4 | 3 x 4 | 12 | 인스타 9컷 + 추가 |
| 2x3 | 2 x 3 | 6 | 6컷 |
| 1x3 | 1 x 3 | 3 | 스토리/세로 띠 |

> 사용자 표기 "3x4 / 2x3 / 1x3"은 **열 x 행** 기준으로 해석한다. (3x3 = 9칸, 3x4 = 12칸, 2x3 = 6칸, 1x3 = 3칸)

#### 3.2.2 셀 인터랙션
- **빈 셀 1탭**: OS 파일 피커(`<input type="file" accept="image/*">`)를 띄워 이미지 선택. 선택 즉시 셀에 채워진다(`object-fit: cover`).
- **이미지가 있는 셀 1탭**: 편집 모드 진입(셀이 강조되고 배경이 어두워짐).
  - 1손가락 드래그 = 이동(팬)
  - 2손가락 핀치 = 확대/축소 + 회전(기울이기)
  - 하단 독: `재업로드` / `삭제` / `완료`
  - 빈 영역(어두운 배경) 탭 또는 `완료` 버튼으로 편집 종료
  - `재업로드`: 새 이미지로 교체하면 transform 리셋
  - `삭제`: 이미지 + transform 제거 후 빈 셀로 복원
- 그리드 페이지 일반 상태에서는 단일 손가락 제스처는 셀 탭으로만 처리(스크롤/줌 충돌 없음 — 페이지 자체가 풀스크린).

#### 3.2.3 플로팅 독(Floating Dock)
화면 하단에 고정. 4개 액션 버튼:

1. **그리드 선 토글**: 한 번 누를 때마다 `흰색 → 검정 → 없음 → 흰색…` 순환. 현재 상태를 아이콘으로 시각화.
2. **레이아웃 변경**: 누를 때마다 `3x3 → 3x4 → 2x3 → 1x3 → 3x3…` 순환. 변경 시 이미지는 위치(인덱스) 기준으로 보존하되, 셀 수가 줄면 초과분은 LocalStorage 별도 키에 백업해두고 다시 늘어나면 복원.
3. **다운로드**: 현재 그리드를 PNG로 합성해 사용자 디바이스에 저장.
   - 캔버스에 셀 단위로 이미지를 그리드 선과 함께 렌더
   - `canvas.toBlob` → `<a download>` 클릭으로 저장
   - 모바일 사파리 호환성을 위해 새 탭 폴백 제공
4. **(선택) 초기화**: 모든 셀 비우기. 확인 모달 필수.

#### 3.2.4 다운로드 이미지 사양
- 해상도: 그리드 가로 1080px 기준(인스타 권장 폭)
- 비율: 화면 비율과 동일하게 유지(예: 3x3 정사각이면 1080x1080, 1x3 세로면 1080x3240)
- 포맷: PNG (투명 미사용)
- 그리드 선: 사용자가 선택한 색상으로 1.5–2px 두께 오버레이

## 4. 모바일 전용 정책

- 뷰포트 메타: `width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no`
- 데스크톱(`window.innerWidth > 768`)에서 접속 시: 중앙에 모바일 프레임(예: 390x844)을 띄우고 그 안에 앱을 렌더한다. 외곽은 안내 문구 + QR코드(현재 페이지) 표시.
- 터치 제스처 충돌 방지: `touch-action: none`을 그리드/셀에 적용.

## 5. 데이터 모델 (LocalStorage)

키: `colorhunt:state:v1`

```ts
type Layout = "3x3" | "3x4" | "2x3" | "1x3";
type GridLineMode = "white" | "black" | "none";

type CellState = {
  id: string;            // 안정적 식별자
  imageDataUrl?: string; // base64 (용량 주의: LocalStorage 5MB 제한)
  transform?: {
    scale: number;       // 1.0 = cover 기본
    offsetX: number;     // 셀 너비 대비 비율 (-1 ~ +1)
    offsetY: number;     // 셀 높이 대비 비율
    rotation: number;    // degrees
  };
};

type AppState = {
  layout: Layout;
  gridLineMode: GridLineMode;
  cells: CellState[];          // 현재 레이아웃 기준
  overflowCells?: CellState[]; // 레이아웃 축소 시 백업
};
```

### 5.1 LocalStorage 용량 한계 대응
- 이미지를 base64로 직접 저장하면 5MB 제한에 쉽게 도달한다.
- **v1**: 업로드 시 `<canvas>`로 리사이즈(최대 단변 1200px) 후 JPEG 0.85 품질로 인코딩.
- **v1.1 검토**: IndexedDB로 마이그레이션(Blob 그대로 저장 가능, 용량↑).
